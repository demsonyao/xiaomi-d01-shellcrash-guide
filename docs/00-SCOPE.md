# 范围、安全与网络拓扑

## 只对以下组合负责

本教程只记录已实测组合：

```text
device_name = D01
rom_version = 1.0.72 release
kernel = 3.14.77
architecture = armv7
LAN = 192.168.31.0/24
main router = 192.168.31.1
```

其他 ROM、国际版、相似外壳型号或不同 LAN 地址，必须重新验证。不要仅凭产品名称相似直接运行写入脚本。

## 推荐拓扑

```text
上级家庭设备/光猫
        │
        ▼
D01 主路由 192.168.31.1
  ├─ ShellCrash + Mihomo
  ├─ DHCP / DNS / 默认网关
  └─ 有线 Mesh 回程
             │
             ▼
       D01 子节点
       只负责接入与回程
```

Mesh 子节点不需要再安装一套 Mihomo。双核运行不会自动分担主路由的连接跟踪、DNS 和透明代理压力，反而会增加策略不一致和回环风险。

## 动手前

- 使用网线连接主路由；
- 保持 `http://192.168.31.1` 可以打开；
- 记录管理密码，但不要把密码写进命令行、截图或 GitHub issue；
- 暂停自动固件升级；
- 确保有一种能恢复直连的方式；
- 先读完 [备份章节](02-BACKUP.md) 和 [安全停止](07-TROUBLESHOOTING.md#安全停止并恢复直连)。

## 风险

开启 SSH 和运行第三方网络组件会改变路由器安全边界，也可能影响保修。错误写 MTD 分区可能永久变砖。本教程不提供自动写回 MTD 的命令。

SmartController 方法依赖已公开的命令注入漏洞。它需要路由管理权限，并只应在你拥有或明确获授权的设备上使用。

## 本方案的数据路径

- TCP：LAN 客户端 → iptables NAT REDIRECT → Mihomo `redir-port` → 规则选择；
- DNS：客户端 → 路由 DNS → Mihomo `:1053` → redir-host 返回真实 IP；
- UDP：LAN 客户端 → 路由普通 NAT → 直连公网；
- IPv6：不透明代理，建议在确认需求前保持关闭。

因此，本方案不是“所有流量都进隧道”。UDP 和未覆盖的 IPv6 会被上游网络按普通直连流量观察到。
